## Платформа и источники

ОС Аврора5.2.1.200, **Qt5.6**, C++11/14, QML/Silica, SQLite, MFW. Проверять API по официальному developer.auroraos.ru, реальному SDK и шаблону. Не угадывать имена методов и не переносить API новых Qt. Документы: docs/REQUIREMENTS.md, docs/ARCHITECTURE.md, docs/CONTRACTS.md.

Основная доступная сборочная среда — MB2 5.2.1.200 у Ильи, это разрешено координатором. Каркас Матвея проверен на BT той же версии. Инструменты не смешивать: MB2 — реальный sfdk/mb2 из SDK, BT — apptool. Новая установка BT не нужна вместо уже работающей MB2. Qt5.15 на хосте — только дополнительные тесты, не доказательство работы Авроры.

C++ отвечает за БД, валидацию и бизнес-правила; QML — за интерфейс. Общая connection используется в главном потоке. Деньги целые копейки, время Unix UTC. QML real может представлять целые до2^53−1; PriceLabel не сужает их до32битного int. Пользовательский SQL только параметризованный. Схему/контракт не менять молча.

## Самостоятельная работа и GitHub

Полный стартовый промпт docs/SETUP_PROMPT.md. Определяй участника через gh api user. Ищи назначенные открытые issues, читай текст, новые комментарии и замечания к собственным PR. Приоритет: последнее явное указание координатора, устранение замечаний, текущая работа, затем доступные назначенные P0/ранний этап. Задачи executor:codex выполняет Codex, не Claude.

По команде «проверь обновления на гитхаб» проверять фактически: аккаунт, origin, ветку, изменения; git fetch origin; свои issues и все новые комментарии; PR, ревью и inline-замечания; инструкции/контракты из origin/main и явно разрешённой integration/app. Ошибка API не означает отсутствие обновлений. После проверки продолжать доступное ТЗ без вопроса «продолжать?». При просьбе только посмотреть ограничиться чтением.

Локальный контекст хранить в игнорируемом .agent-local/<login>.md: issue/ветка/SHA, указания, проверки, блокер. Существенные результаты публиковать в GitHub. Бесконечный фоновый опрос и неподдерживаемую работу после завершения сессии не обещать.

Агент сам выясняет среду, выполняет разрешённую установку, команды, код, проверки, коммиты, push своей ветки, PR и отчёты. Технические вопросы адресовать ggmaster913 прямо в GitHub; человека не использовать для передачи логов и команд. При блокировке продолжать независимую часть. Человек нужен для входа/MFA, недоступного системного шага/пароля, доступа или решения за пределами разрешений. Необходимые действия объединить в одно короткое сообщение с причиной и следующим шагом; уже данное разрешение повторно не запрашивать. Перезагрузку согласовать после сохранения работы.

## Ветки, проверки и приёмка

Ветки feat/<issue>-<имя> или fix/<issue>-<имя>. Обычно PR в main; новое оформление по явному заданию идёт в integration/app. Интеграционная ветка WIP, не считать её наличие успешной сборкой. Существующие изменения сохранять; reset --hard/clean/скрытый stash не применять. Прямые push в main, самостоятельные слияния участниками, force-push и удаление чужих веток/репозиториев запрещены без явного разрешения координатора.

Перед работой оставить в issue ветку, разрешённые файлы и первый проверяемый результат. О блокере сообщать сразу; дальнейшие отчёты — по существенному результату, ошибке и передаче PR. При настройке первый статус через5мин, через10мин точная причина отсутствия сборки; человек не должен засекать время и напоминать.

Для полного результата PR содержит Closes #N, реальные команды/среду/результаты и ограничения. Для части — «Часть #N», без закрытия всей задачи. Без SDK-проверки — draft. Ошибка, пропуск теста и макет должны быть обозначены честно. Слово «готово» требует доказательства соответствующей проверки.

main сохраняет проверенную сборку. После интеграции — сквозной запуск в целевом эмуляторе. Проверка host SQLite/Qt/JS и снимок макета не заменяют RPM и запуск Авроры. Исходники и интерфейсы соседних PR брать только по согласованной ветке/указанию.

## Безопасность и сдача

Все тексты на русском. Токены/пароли/ключи подписи/.env/пользовательские БД/IDE-настройки/установщики не коммитить. Лицензии стороннего кода сохранять; чужой токен из MFW-примера не переносить. Вход, каталог и оплата демонстрационные, реквизиты карты не собирать.

Новая красота не отменяет работоспособность: анимации короткие и событийные, останавливаются вне активного экрана, без тяжёлых постоянно работающих эффектов. Не добавлять зависимости/сервер/новые экраны за рамками issue. После заморозки только исправления, демо и сдача.

Публичный Мос.Хаб, README, базовый файл с фактически использованными ИИ, презентация и доступные ссылки обязательны. Использование плагина/SDK/модели не заявлять без фактического выполнения.
