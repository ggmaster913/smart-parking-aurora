# План реализации «Умной парковки»

> Для ИИ-исполнителей: выполняйте задачи по своему GitHub issue и правилам AGENTS.md. Для последовательной реализации плана координатор применяет навык `superpowers:executing-plans`. Новые внутренние подагенты не заменяют четырёх участников команды.

**Цель:** получить собирающийся прототип ОС Аврора со сквозным сценарием парковки и подготовить обязательную сдачу.

**Архитектура:** нативный шаблон SDK, C++-сервисы с фиксированными QML-интерфейсами, одна SQLite connection. Каталог в JSON, вход и оплата симулируются. MFW подключается по официальному примеру отдельно от основной бизнес-логики.

**Стек:** Aurora SDK BT 5.2.1.200, Qt из SDK, C++/QML/Silica, qmake, SQLite, MFW, Qt Positioning.

**Спецификация:** `docs/REQUIREMENTS.md`, `docs/ARCHITECTURE.md`, `docs/CONTRACTS.md`.

## Общие ограничения

- Все задачи выполняются в рамках переданного issue, PR направляется в `main`.
- Общие интерфейсы и миграции меняет интегратор; чужие модули — только по согласованию.
- Нельзя считать приложение собранным по проверке JSON, SQLite или по просмотру QML.
- Денежные суммы — целые копейки, время — UTC, оплата и вход обозначены как демо.
- Публичный проект на Мос.Хаб, исходники под MIT, README, базовый файл и презентация обязательны.
- Точные данные об инструментах, тестах и реализованных функциях фиксируются по факту.
- Новые функции прекращаем за 90 минут до D. Дедлайн ориентировочно 03:37 МСК 8 ноября, подтверждён только остаток «около 6 часов».

## Пять условий для ревью

1. Нет/запрещён GPS или подложка карты: понятное состояние и явный выбор демопозиции, без выдуманных реальных координат. Проверяет задача карты.
2. Двойное нажатие оплаты/продления и повтор после рестарта: один результат на operationId, отсутствие двойного списания. Проверяет задача бронирования.
3. Сон/перезапуск во время парковки: отсчёт по сохранённому UTC, истёкшая сессия не оживает. Проверяет задача бронирования.
4. Смена пользователя, чужая машина/сессия и специально введённые SQL-символы: нет доступа к чужим данным или изменения запроса. Проверяют задачи профиля и бронирования.
5. Повреждённый JSON/ошибка записи БД: понятная ошибка, отсутствие частичной миграции, потери пользовательских данных и молчаливого повторного посева. Проверяет задача каркаса/данных.
