## 1. Проверка компьютера

Определи ОС, архитектуру CPU, память, свободный диск, установленный Git, существующие Docker и Аврора SDK. Не устанавливай второй SDK той же версии поверх существующего. Проверяй Docker не только по наличию команды: `docker version` должен показывать клиент и сервер.

На macOS: `uname -m` различает `arm64` и `x86_64`. На Windows получи архитектуру средствами ОС/PowerShell. Используй путь без пробелов и кириллицы, например отдельный каталог `C:\dev\smart-parking-aurora` на Windows или каталог `Documents/Code/smart-parking-aurora` на Mac. SDK workspace должен включать этот проект. Не монтируй весь домашний каталог в контейнер вместо рабочей папки.

Официальные требования: не менее 45 ГБ свободного диска, рекомендованы 16 ГБ ОЗУ. Меньший объём памяти явно укажи как риск. Не удаляй чужие файлы для освобождения места.

## 2. Docker и SDK

Сначала изучи официальную инструкцию: https://developer.auroraos.ru/doc/sdk/app_development/setup/docker_install. Установи и запусти Docker Desktop для своей ОС/архитектуры, если он отсутствует. На Windows проверь необходимые компоненты виртуализации и требования установщика. Пользователь сам подтверждает системные диалоги, вводит пароль администратора и выполняет обязательную перезагрузку, если они потребуются. Не обходи ограничения системы и не меняй глобальные настройки безопасности ради удобства.

Скачай **Aurora SDK BT 5.2.1.200** только с официального портала:

- Список установщиков: https://developer.auroraos.ru/downloads/archive/sdk_bt
- Mac ARM64: https://developer.auroraos.ru/downloads/sdk_bt/5.2.1.200/macos%20%28arm64%29
- Windows: выбери Windows в списке для той же версии.
- Mac Intel: выбери macOS (x86) для той же версии.

Выбирай Application SDK **BT**, не MB2 и не Platform SDK. Не подставляй угаданный URL бинарного файла или Docker-тег. Проверь имя/версию и опубликованную контрольную сумму фактически скачанного установщика. Online/offline выбирай по доступной сети; номер релиза одинаковый. Не переходи на другую версию молча.

Инструкции по платформам:

- https://developer.auroraos.ru/doc/sdk/app_development/setup/setup_macos
- https://developer.auroraos.ru/doc/sdk/app_development/setup/setup_windows

На Windows отдельно проверь требования к Visual C++ Redistributable, PowerShell и символическим ссылкам из официальной инструкции. Применяй только необходимые настройки текущего пользователя, сообщая человеку о требуемом системном действии.

Установи IDE, Build Tools и эмулятор. В SDK BT сборка работает через Docker, эмулятор — QEMU. Старый VirtualBox устанавливать для этого комплекта не нужно. Версия SDK и образа ОС должны соответствовать выбранной командой версии. Выбирай доступный комплект сборки по его реальному имени в IDE. Не угадывай архитектуру эмулятора по архитектуре ноутбука.

## 3. Проверка сборки

Официальное создание проекта: https://developer.auroraos.ru/doc/sdk/app_development/work/create/create_new_project.

Создай временный проект мастером «Приложение Qt Quick для ОС Аврора», система сборки qmake. Собери RPM, запусти эмулятор и приложение. Для командной строки BT использует `apptool`: сначала изучи справку установленной версии и https://developer.auroraos.ru/doc/sdk/app_development/build/build_tools. Не выдавай `sfdk` из MB2 за команду нашего BT.

Если тебе назначено bootstrap issue, создай командное приложение **SmartParking** в своей ветке по указанным там правилам и отправь PR. Иначе временный тестовый проект оставь вне командного репозитория: он только доказывает готовность твоего окружения. Пока bootstrap не слит, можно готовить свой модуль в ветке и draft PR, но нельзя заменять общие файлы чужим шаблоном.

## 4. Отчёт в своём issue

Напиши одним комментарием:

```text
ОС / архитектура / ОЗУ / свободный диск:
Docker клиент и сервер, версия:
SDK: BT 5.2.1.200, путь:
Версия образа Авроры и реальное имя комплекта:
Сборка: команда или действия IDE, exit code/короткий лог:
RPM: путь и архитектура:
Эмулятор: приложение запущено / точная ошибка:
Скриншот или короткая запись:
Следующий шаг / блокировка:
```

Пароли, токены, ключи подписи и установщики в issue/PR не публикуй. Если для установки нужно единственное действие человека, сформулируй его точно, а остальную доступную работу продолжай.
